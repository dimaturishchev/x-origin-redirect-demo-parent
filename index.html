Cross-origin sandbox top-navigation repro

Top document — Origin A. …

This page embeds a cross-origin child (Origin B) inside a sandboxed iframe. The child tries to navigate this top window to another URL on load, with no user gesture. The sandbox grants allow-top-navigation-by-user-activation — which per spec should require a user activation — but not allow-top-navigation. So a conforming browser must block the gesture-less attempt. The known iOS-Chrome quirk is that it doesn't.

Tip: you can also preset it with ?frame=<url> in this page's own URL.

Top-document log

If the top window gets redirected you'll land on the "redirect succeeded" page instead of seeing this log — that's the positive result. If you stay here and the log shows the frame's blocked attempts, the browser enforced the gesture requirement.
